## Decisions for this update

Proposed 9 November 2026; to be agreed with the operator before Stage 1.

1. **Use the gameplay-shape route list** for both the Stage 0 baseline and the post-update
   capture, so both sides match route for route. It becomes the new build's `raw-routes.txt`.
2. **Compare catalogs like with like** (fresh cache against fresh cache, or pass
   `--baseline-catalog` at a fresh-cache folder), never a loaded-cache catalog against a
   rebuilt one.
3. **Expect a new build, not a hotfix** (new map, new weapon, new gadget, new attachments,
   balance pass). The skill's decision step still decides.
4. **Ignore REDSEC** items in the notes.
5. **Never decode or open a `materialgrid_win32` file directly.** Use
   `scripts/frosty-material-grid-inventory.py`. The Mini Scout change is a damage-curve
   change (bullet file), not a grid change, unless the capture says otherwise.
6. **The NSW4 Carbine goes through "Adding a new weapon"** (guide Stage 9). The ADS-17
   6GHz Signal Jammer and the M142 MRAS are recorded for the gadget and vehicle notes only;
   they are not site work.

## Follow-up: the "99 damage" note line (10 November, after the run closed)

A fix line in EA's notes, that damage "could display as 99 damage next to the crosshair under
certain circumstances", was never put on this checklist; the operator raised it. The notes
text was not saved anywhere in the repos, so the exact line and its heading cannot be quoted
here. Traced by one worker (`W99\`):

- **Nothing stored defines the kill threshold** in either build: no base health value, no
  lethal comparison, no rounding flag. 457 health, damage and rounding rows in the soldier,
  mutator and mode-setting registries are unchanged between the builds.
- **The display rule is known from 2.1.1.0** (`docs/frosty/UI_TEXT.md`, "Hit indicator damage
  numbers"): the outgoing number cells show floor(x) when 99 < x < 100, so a non-lethal total
  of 99.18 to 99.53 shows "99" by design. The five `HitIndicatorOutgoingNumberCell_*` routes
  and `HitIndicatorNumber_SoldierDBD` are in the 2.1.2.0 catalog but were **not captured**, so
  whether 2.1.2.0 changed that rule is unknown. The changed crosshair and hit-indicator logic
  routes that were captured show only re-bake ids and layout defaults.
- **The site is unaffected either way.** Its shots to kill (health 100) equals a float32
  running-sum test for every weapon, ammunition type, damage tier and zone mix: 0
  disagreements. 697 combinations total between 99.0 and 99.63, none lies within 0.0001 of
  100 without being exactly 100, so no float error can turn a kill into a displayed 99.

  the display expression with 2.1.1.0. No in-game reading is needed.
