What an attachment record does—and does not—tell you

An Attachment record identifies a choice, its category, cost and progression. Its gameplay effects usually live elsewhere: an Ability branch selects unlocks, a WB part supplies WME effects, and a separate GS binding selects recoil or dispersion modifiers. The same menu name can select different effects on different weapons.

This guide covers the source structure and the pinned Analyzer’s current composition rules. It is not a recommendation to fit one universally “best” loadout, and it does not convert an unexplained hash, a marketing description or a package suffix into a percentage.

Read a value together with its owner, build, descriptor and selection route. A familiar field name or an identical number on another object is not enough to transfer its meaning.

EvidenceWhat it establishesWhat it does not establish
Stored game valueAn exact field on the selected serialized owner.Does not by itself establish activation, effective units or the native operation.
Source mappingA field name or association qualified by its declaring class, descriptor key and member schema.Schema-based name transfer is distinct from an inherited value and from native execution.
Inherited / registry defaultA base-class value or a named registry leaf, identified separately in the text.Never silently replace or average with the selected export’s own value.
Game description / UI summaryThe named card or menu statement; summaries retain their summary label.Does not establish a gameplay measurement or an exact UI-to-gameplay asset join.
EA patch notesAn EA statement at the explicitly cited update version.Does not prove the saved game build still behaves that way.
InterpretationA proposed explanation, correspondence or hypothesis.Does not establish a native equation or validated gameplay effect.
Analyzer modelA rule or calculated output in the pinned Analyzer software.Source-backed inputs do not automatically validate the software equation as native behavior.
In-game observationThe specifically cited game capture or test.Its result retains its weapon, loadout, build and measurement scope.

The colors identify the kind of evidence, not a confidence score. Field names, values and interpretations retain the qualifications beside them.

Null, zero, false and −1 are different observations. Do not turn an absent boxed default into zero, interpret −1 as “infinite,” or add the members of an unnamed tuple. “No join found” describes the checked scope, not proof that a feature does not exist.

Slots, prerequisites and point cost

Physical mounts are separate from catalog categories

Analyzer model The Analyzer separates WEAPON_ATTS.slots from category availability lists. A grip can remain in the grip catalog while occupying a shared rail. A combo device is one selected item and must contribute its cost and effects only once.

Shared source-supported mount examples:
rail: { accepts: ['grip', 'laser', 'light'] }
rail: { accepts: ['laser', 'light'] }

Selected shared mount:
atts.rail = { type: 'grip', id: 'canted_stubby' }
atts.rail = null   // explicitly empty

Separate mount example:
grip: { accepts: ['grip'] }

resolveMountAttachments() validates the selected category and weapon availability, then merges weapon-specific modifiers. normalizeMountAtts() handles older shared selections: an explicit rail value, including null, takes precedence over stale category keys. Changing weapon resets the slot selections.

Use the cost field and per-weapon selection

Class_a9b2eb87.Field_6ee865a5 is the point-cost field. Package suffixes such as _W10 and _W50 must not be used to infer a price.

The L540 current-source check reads cost 10 on six offered AG Coating owners: UInt32 at offset 128, bytes 0a000000. Its same-owner Canted Iron Sights control is 5 points. This is serialized cost evidence, not proof of every unlock or compatibility condition.

The Analyzer uses selected sight overrides, per-weapon ammo costs and the magazine’s own cost. A shared or combo mount counts once. Above 100 points the UI warns; it does not reject the build. These are site policies, not a source-derived weight model.

The source census distinguishes add, multiply and override records. It does not establish one universal native execution order across modifiers on the same field. The Analyzer’s explicit composition order must be labeled as software behavior.

Do not confuse these three examples:

Add:       duration + (−0.0006)
Multiply:  recoveryFactor × 1.2
Override:  duration = 0.05

A source package named P10 does not universally mean +10%.

Tier signs, array order and clamping

Analyzer model The source arrays are zero-based and ordered. Sum contributions on the relevant axis, then clamp once. Clamping after each attachment can change the result, especially when one shift increases an index and another decreases it.

Analyzer model
AxisPinned Analyzer index ruleParticipating inputs
ADS-inclamp(defAds − magShift + gripMod + barrelMod)Magazine, grip, per-weapon barrel ADS term.
ADS movementclamp(defAms − magShift − gripShift − ammoShift)Axis-specific signed terms; retain documented optic handling separately.
Moving ADS minimumclamp(indexOf(baseMinimum) + Σ movingAdsSpreadTierMod)Grip, laser, barrel and magazine.
Hip minimumclamp((override ?? base) − Σ hipSpreadTierMod)Muzzle, barrel, laser, grip and ammo.
Sprint recoveryclamp(sprintBaseIndex − Σ sprintRecoveryTierShift)Magazine, grip, ergo, barrel, muzzle, laser, light and ammo.
Deploy / undeployclamp(deployBaseIndex − Σ deployTimeTierShift)The same eight categories, but a separately summed timing axis.

The table preserves the documented catalog equations rather than inventing a single sign convention. TierShift and TierMod have different histories. Absent modifier fields contribute zero in software; that does not establish a zero operand in the source.

A concrete moving-spread lookup

M240L base moving ADS minimum: row 3 = 0.32°
75 Rnd magazine source shift: +1
Final selected row:            row 4 = 0.22°

This changes the minimum, not IncreasePerShot or the maximum.
Do not multiply 0.32 by a guessed “10%” from the package name.

The moving array’s ordinary row values are 0.68, 0.55, 0.43, 0.32, 0.22, 0.13 and 0.05. Its four raw columns preserve state distinctions; the extra jumping/sprinting column is not an eighth tier.

Hipfire rows have two separate source ranges

The 18-row hip table has an ordinary range at rows 0–10 and a separate shotgun range at rows 11–17. Only Field_1867639b (standing) and Field_c5401fc2 (moving) currently set runtime minima. The other five columns retain probable state meanings rather than newly modeled stances.

Buckshot, 00 Buckshot and Flechette on the documented shotgun records use ammo modifier −9; the hip subtraction equation adds nine to the source coordinate. Slugs do not apply that shift. Never globally sort these rows or flatten seven columns into seven tiers.

Muzzles: recoil, recovery and spotting

Amount and variation are different axes

Analyzer model ADS recoil amount is calculated from the accepted effective base times a per-weapon factor raised to the sum of attachment amount tiers. Variation instead uses the raw group’s variation and exponent. Hip has its own group. A modifier affecting both aim states must be applied to each intended group, not copied from the finished ADS output.

Barrels: ADS timing, velocity and spread

Per-weapon ADS steps

Source mapping The barrel generator follows the selected Ability/WB animation and FOV effects and requires their signed ADS steps to agree. Agreeing paired effects count once. It does not combine the separate GS route into a guessed second adjustment.

The retained generation has 234 source records for 233 unique selections because KTS100 Short has two agreeing records. M4A1 Basic remains 200 ms with defaults, and both VSSM barrel choices retain 250 ms. The conflicting VSSM GS route is not silently substituted for the accepted WB route.

Read-only catalog comparison described by the repository:
python scripts/frosty-barrel-ads.py --root <Frosty-export-root> --check

Output field: BARRELS[].adsTimeTierModByWeapon
Conflicting or missing required source mappings stop generation.

Velocity tiers are not damage or drag tiers

After resolving the selected ammunition treatment:
preciseVelocity = preBarrelVelocity × 0.8 ** (−barrel.velTierMod)

Use a valid legacy velMult only when no tier field is present.

The belt-box case: why text is not enough

Analyzer model M240L 75 Rnd has a linked +1 moving-spread index, changing 0.32° to 0.22° with other modifiers absent. Its 50- and 100-round boxes do not carry that shift. M60 has 50- and 100-round choices, not the 75-round option in that reviewed export.

L110 / Minimi and M123K / MG4K 200-round packages do not have a magazine moving-spread operand in the retained trace. Matched mid-strafe HUD captures support no difference from the 100-round box, so the previous estimated penalty was removed. Their descriptions still claim reduced moving-ADS accuracy; the mismatch is retained rather than silently rewritten.

Camera-recoil ladder is not recoil amount

Source mapping The GCR paired fields Field_7f1bb9d4 and Field_9532eb28 hold IdleCameraRecoilWhenZoomedAmount and CameraRecoilWhenZoomedAmount in Class_539cff9b. The enabled override values follow a 14-value ladder, from −0.5 at 1× to about 0.762266 at 10×.

Those values must not be converted into a percentage reduction in projectile kick or substituted for GS RecoilAmount. A camera/render adjustment and the simulated weapon recoil path are different outputs.

Analyzer model The site displays multiplicative weapon-sway change from sight, muzzle, magazine and barrel factors. A factor 1.5 means +50%; 0.6666667 means about −33.3%; 0.4444444 means about −55.6%. Optics carry no weapon-sway factor in this model; the iron-sight reduction is weapon-specific.

In-game observation M4A1 recordings support a vertical sway ratio around 0.68 versus ROX, while BROD 3 recordings show no iron-sight reduction. The combined M4A1 iron-sight/20-round-magazine example also supports multiplicative composition within that capture scope. This is bounded evidence, not all-weapon camera-sway validation.

Variable High and Thermal sights additionally have a source WME_ADSMoveSpeed_M05 step, represented by adsMoveSpeedTierShift: 1. M4A1 menu captures show ADS movement 0.82 → 0.75 and Mobility 74 → 72. Other optic inputs and inline ADS settings retain their stated source limits.
