Gadgets

Frosty paths, field identities, selected gadget routes and the limits of the evidence.

Updated 10 October 2026 · Source reference: build 1.4.3.5, Head 4909002
Historical evidence is labeled in place. UI summaries: client 1.4.3.1. No gadget runtime model is claimed.
Covers leads through L4035. The expression-graph listings read for L4026 are from build 1.4.3.0; the other graph leads (L4021, L4029, L4030) do not restate their build. Tunable defaults come from the saved tunable files.

Reading the evidence

This guide covers gadget research, not a released Analyzer gadget simulation. Current source discussions refer to build 1.4.3.5 / Head 4909002 unless a passage identifies older evidence. Card text is retained from client 1.4.3.1 / Head 4892087. UI descriptions below are summaries; follow the metadata record for the exact wording.

Read a value together with its owner, build, descriptor and selection route. A familiar field name or an identical number on another object is not enough to transfer its meaning.

EvidenceWhat it establishesWhat it does not establish
Stored game valueAn exact field on the selected serialized owner.Does not by itself establish activation, effective units or the native operation.
Source mappingA field name or association qualified by its declaring class, descriptor key and member schema.Schema-based name transfer is distinct from an inherited value and from native execution.
Inherited / registry defaultA base-class value or a named registry leaf, identified separately in the text.Never silently replace or average with the selected export’s own value.
Compiled graph ruleAn operation sequence read from a compiled expression-graph listing: which tunables it imports, how it combines them and which effect assets it applies.Does not supply the tunable values, which are separate defaults. Function meanings are named from how they are used and are marked inferred; undecoded operations are not read.
Game description / UI summaryThe named card or menu statement; summaries retain their summary label.Does not establish a gameplay measurement or an exact UI-to-gameplay asset join.
EA patch notesAn EA statement at the explicitly cited update version.Does not prove the saved game build still behaves that way.
InterpretationA proposed explanation, correspondence or hypothesis.Does not establish a native equation or validated gameplay effect.
Analyzer modelA rule or calculated output in the pinned Analyzer software.Source-backed inputs do not automatically validate the software equation as native behavior.
In-game observationThe specifically cited game capture or test.Its result retains its weapon, loadout, build and measurement scope.

The colors identify the kind of evidence, not a confidence score. Field names, values and interpretations retain the qualifications beside them.

A tunable default is the value shipped in the saved tunable file, with its stored minimum and maximum. The game can override it remotely, so a default is not a measured match value. Compiled graphs mostly import tunables by name and hold the rules; the effect assets they apply hold further numbers. The meaning of a number inside an effect asset is inferred from the asset name unless its field is named by a stored link.

Null, zero, false and −1 are different observations. Do not turn an absent boxed default into zero, interpret −1 as “infinite,” or add the members of an unnamed tuple. “No join found” describes the checked scope, not proof that a feature does not exist.

Defibrillator

Game description · summary Revives squad members and teammates; charge for a full-health revival; can damage enemies.

Stored game value The saved sources contain a 13-row curve candidate, two six-entry revive affectors and a separate damage affector. The older FasterRecharge package has inline 1.5 and 1.0 operands; these are not established recharge multipliers.

Source mapping Field reference

TraitSprintSpeedMultiplierSelected by Supercharge.The receiving setter and formula are unproved.

EA patch notes Update 1.2.3.0 gives 0.35 s minimum charge and 1 s full charge. This is charge duration, not total interaction time.

Compiled graph rule SimEx_Defib computes the charge time as clamp(TimeToFullCharge − ActiveReviveTimeReduction, ChargeTimeMinimum, TimeToFullCharge) (L4026). The reduction is used only when a component lookup on the user returns a value; reading that as “has the active-revive upgrade” is inferred from the tunable name and the guard. The target search radius is the larger of the friendly and enemy range tunables. On a friendly target the graph applies AffectorRevive_Defibrillator_Ranked with parameter 2.0, using entry 6 while the reviver’s CurrentAction equals 24 and otherwise an integer slot value. On an enemy it applies Affector_Damage_Defibrillator with parameter 0.5 and, for gadgets in range and angle, Affector_DestroyGadget. Affector_Supercharge gets parameter 5.0 when an upgrade test passes. Which branch is the enemy branch is inferred from the effect names. A separate revive graph, SimEx_GetRevive, applies AffectorRevive_Defibrillator_Revive with parameter 0.5 (L4023).

Registry default Tunable defaults (minimum, maximum): Defibrillators_TimeToFullCharge 1.0 (0.1, 3.0); Defibrillators_ChargeTimeMinimum 0.3 (0.1, 1.0); ActiveReviveTimeReduction 0.7 (0.5, 1.5); friendly range 2.0 and enemy range 1.5; collision radius 0.9 friendly and 0.6 enemy; gadget range 2.0 and angle 45. The charge time is therefore 1.0 s without the reduction and 1.0 − 0.7 = 0.3 s when the full reduction applies (L4034). The registry weapon row stores 3 magazines, 3 initial rounds and a replenish delay of 4 (L3310). These are shipped defaults and can be overridden remotely.

EA patch notes Against EA’s 1.2.3.0 statement, the stored full charge of 1.0 s equals EA’s 1 s, and the stored minimum of 0.3 s is 0.05 s below EA’s 0.35 s (L4035). The guide does not explain the gap.

Stored game value The effect assets hold the amounts the graph does not. AffectorRevive_Defibrillator_Revive and _Ranked each hold six entries: 50, 60, 70, 80, 90, 100. They are read as health restored, chosen by entry index; the meaning comes from the asset name (L4035). Affector_Damage_Defibrillator holds six InitialDamage entries, 50 to 100 in steps of 10 (L3381; the field is named from registry rows). Which entry applies when is not read. The revive effects hold six entries while the graph names entry 6, so whether entry numbering starts at 0 or 1 is not settled.

Not established Curve evaluation, which revive and damage entry applies, the charge-to-health composition, the condition for the charge reduction, and the missing FasterRecharge selector owner. The charge-time rule contains no curve and no multiplier, but the rest of this large graph is partly undecoded, so the 13-row curve and the older FasterRecharge 1.5 / 1.0 operands are not placed in it.

Adrenaline Shot

Game description · summary Temporary sprint boost, reduced explosive/incendiary damage, and resistance to or removal of flash/stun effects.

Stored game value SimEx_TriggerAdrenalineShot imports named Suppression, Flak and RemoveDebuffs affectors. Historical payloads are i32 −100, Float32 0.8 and u32 247138971. The inspected Ability and U_AdrenalineShot import tables did not select that trigger.

Compiled graph rule The trigger graph applies three effects to the user, Affector_Flak_AdrenalineShot, Affector_Suppression_AdrenalineShot and RemoveAffector_Debuffs_AdrenalineShot, each with parameter AdrenalineShot_Duration (L4026). It runs when a state compare passes; an extra block for the Granite flag is unresolved.

Stored game value The three historical payloads equal the stored values of these effects. Float32 0.8 is the multiplier of the flak effect, whose explosive flag is set. Its field is named DamageReceivedMultiplier by a stored registry import in other effects of the same class, so on that reading the shot takes 20% off explosive damage (inference, L3315, L4035). The i32 −100 is the value of the suppression effect, and u32 247138971 is the value of the debuff-removal effect; the meaning of each is unread. A self-heal effect, Affector_SelfHeal_AdrenalineShot, stores InitialHeal 0 and HealOverTime entries 5, 10, 12.5, 15, 17.5, 20 and further ranks; it is tied to the shot by name only (L3315).

Registry default AdrenalineShot_Duration 8 (minimum 0.1, maximum 10) (L4034); registry duration 8 and rank 5; WB_AdrenalineShot: capacity 1, 1 magazine, auto-replenish delay 45; ability active time 1 and recharge 0 (L3310). Defaults can be overridden remotely.

Not established Which ability or equipment selects the trigger graph, how the rank selects a heal entry, the unit of the heal entries, and the meaning of −100 and 247138971.
